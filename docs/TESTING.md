# Полевая проверка

1. Делегация NS из родительской зоны ведёт на публичный IP сервера; UDP/53 доступен
   от рекурсоров. В серверных логах пароль не выводится.
2. На телефоне выбран реально доступный DNS оператора. Старт получает
   аутентифицированный PONG и начинает слушать SOCKS только после этого.
3. Telegram открывает сообщения/картинки, браузер с SOCKS5h скачивает HTTPS-файл.
   Сравните SHA-256 исходного и скачанного файла. SOCKS5h нужен для remote DNS;
   клиент Крота и так передаёт доменное имя серверу без локального lookup.
4. Проверьте 1, 2 и 4 одновременных TCP-потока; конвейер 8/12/16; размеры
   300/600/900. Запишите RTT, QPS, полезную скорость и частоту разрывов.
5. Повторите с экраном off в течение 15 минут, при переключении Wi-Fi/мобильной
   сети и при рестарте сервера. Смена сети закрывает старые TCP-потоки — приложение
   должно подключить новые. После рестарта сервера старые TCP не восстанавливаются.
6. Плохой пароль, неизвестная зона, битый DNS-пакет, неподходящий резолвер должны
   дать timeout/ошибку в журнале, не crash. Экспорт журнала не включает пароль.
7. LAN off: доступен только loopback. LAN on: ноутбук подключается к IP телефона,
   но чужие устройства в той же сети тоже смогут использовать прокси без пароля.
8. UDP ASSOCIATE должен возвращать SOCKS reply 7 (unsupported), не зависать.

Не объявляйте подтверждённую скорость до измерений на реальном рекурсоре.
Скорость DNS-несущей, полезный TCP throughput и скорость приложений различаются.
NULL и A дополнительно проверяются на каждом операторе: промежуточные резолверы
могут удалять, ограничивать или переставлять записи. Silent-only authoritative
сервер может быть несовместим с проверками SOA/NS у некоторых рекурсоров.

## Регрессии v0.1.1–0.1.2

JVM-тесты вставляют настоящий UDP DNS relay перед Python-сервером и намеренно
теряют первые 2 запроса DATA, затем задерживают ответ на 800ms. Второй тест
теряет первые 6 попыток DATA: седьмая должна доставить блок, не порвав SOCKS TCP.
Проверяется совпадение всех 8192 байт и уникальность QNAME при каждом повторе.
Системные DNS тестируются с IPv6 первым в исходном списке: IPv4 оператора должен
быть первым кандидатом, чужие DNS не добавляются.
Третий тест теряет 9 попыток подряд — больше, чем 7 попыток одного RPC. Пока
heartbeat получает PONG, блок повторяется, поток не рвётся, байты доставляются ровно
один раз. Журнал показывает согласованный chunk («Chunk N Б (запрошено M)»);
сервер раз в 15s пишет число запросов зоны, отброшенных из-за EDNS0 < 1232.
